# tools/ — เครื่องมือสำหรับย้าย extension ไปเว็บ isurvey ตัวใหม่

## probe-isurvey.js — ตัวสำรวจโครงสร้างหน้าเว็บ

เก็บ "แผนที่" ของหน้า isurvey (framework, id ของฟิลด์, โครงสร้างแถว) เพื่อเอาไปสร้าง
selector registry ให้ extension ทำงานได้ทั้งเว็บเก่าและเว็บใหม่

### วิธีใช้

1. เปิดหน้าเคลม isurvey ให้เห็นแท็บที่มีช่อง **ค่าบริการ / ค่าเดินทาง / ค่าเรียกร้อง**
   (ต้องเปิดแท็บนั้นค้างไว้ — ExtJS ทำลาย component ของแท็บที่ไม่ได้เปิด)
2. กด `F12` → แท็บ **Console**
3. ถ้า Console ขอให้พิมพ์ `allow pasting` ให้พิมพ์แล้ว Enter ก่อน
4. เปิด `probe-isurvey.js` → คัดลอกทั้งไฟล์ → วางใน Console → Enter
5. ผลจะถูกคัดลอกเข้า clipboard อัตโนมัติ → เอาไปวางส่งกลับ

ถ้าคัดลอกอัตโนมัติไม่สำเร็จ:

```bash
copy(__SE_PROBE__)
```

### ผลลัพธ์ 2 ระดับ

| ตัวแปร | ขนาด | ใช้เมื่อ |
|---|---|---|
| `__SE_PROBE__` | ~20–40 KB | **ค่าเริ่มต้น** — พอสำหรับสร้าง registry (guesses + rows + framework) |
| `__SE_PROBE_FULL__` | ใหญ่กว่ามาก | ตอนต้องขุดเพิ่ม — ดัมป์ component/DOM ทั้งหมด |
| `__SE_PROBE_OBJ__` | (object) | ส่องใน Console เองได้ |

### ความเป็นส่วนตัว

ไม่เก็บ "ค่า" ในช่องกรอกใดๆ — ไม่มีเลขเคลม ชื่อลูกค้า ยอดเงิน
เก็บแค่ id / ชนิดช่อง / ข้อความ label / ตำแหน่ง เท่านั้น
(ยกเว้น `value` ของ radio/checkbox เช่น `"ใน"`/`"นอก"` ซึ่งเป็นค่าคงที่ของระบบ ไม่ใช่ข้อมูลเคลม)

### วิธีตามหาฟิลด์ (7 ชั้น เรียงตามความน่าเชื่อถือ)

1. `id` เดิมตรงเป๊ะ
2. `name` เดิมตรงเป๊ะ
3. token ของ id เดิมโผล่ที่ขอบคำ (เช่น `SUR_INVEST`) — กลางคำหักคะแนน
4. **radio จับจาก `value`** (`"ใน"`/`"นอก"`) — ผูกกับ business logic ไม่ใช่ชื่อ element
5. ข้อความของตัวเอง (ปุ่ม/แท็บ/หัวข้อ)
6. **แถว × คอลัมน์** สำหรับช่องเงินในตารางค่าใช้จ่าย
7. label ไทยที่อยู่ใกล้

> **ข้อ 6 สำคัญที่สุด** — ช่องเงิน (ค่าบริการ/ค่าเดินทาง/ค่าเรียกร้อง/ค่าคัดประจำวัน)
> ใช้ label ร่วมกันทั้งแถว แยกกันได้ด้วย *ตำแหน่งคอลัมน์* เท่านั้น
> กติกา: เรียง input ในแถวซ้าย→ขวา แล้วแมป
> 3 ช่อง = `[จำนวน, เสนอ, อนุมัติ]` · 2 ช่อง = `[เสนอ, อนุมัติ]` · 1 ช่อง = `[อนุมัติ]`

## fixtures/ — หน้าจำลองไว้ทดสอบ

เปิดไฟล์ตรงๆ ในเบราว์เซอร์ได้เลย (probe รันอัตโนมัติ ดูผลใน Console)

| ไฟล์ | จำลองอะไร | ผลที่ควรได้ |
|---|---|---|
| `legacy-page.html` | เว็บเก่า: ExtJS 6.2 + id เดิม + layout absolute | **34/34 ตรงเป๊ะ** ทุก key ชี้ id เดิม |
| `redesign-page.html` | เว็บใหม่สมมติ: ไม่มี ExtJS + id เปลี่ยนหมด + layout flex | **34/34 เจอ** ผ่าน name/label/คอลัมน์ |

`redesign-page.html` คือกรณีที่โหดที่สุดเท่าที่จะเจอ (id เปลี่ยนทุกตัว + คนละ framework)
ถ้า probe ยังหาเจอครบ แปลว่ากลยุทธ์การค้นใช้ได้จริง

ทั้งสองไฟล์จะถูกใช้เป็น fixture ของ `resolver-spec.mjs` ตอนทำ Stage 1 ต่อไป
